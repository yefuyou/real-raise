# 城市选择器 UX 方案（2026-07-26 历史实施稿）

## 结论

不做分页，也不继续使用原生长下拉框。城市只有 30 个，分页会让用户多一次“翻页—再选择”的操作；更合适的是紧凑的可搜索城市选择器。

当前实现位于 `src/App.tsx` 的原生 `<select>`，选项直接来自 30 城目录。它适合数据工程内部工具，但会让输入区域出现一条很长的选择列表。

## 目标体验

收起时只占一行：

```text
所在城市       [⌖ 合肥                         ▾]
```

打开后显示一个有限高度的选择面板：

```text
┌────────────────────────────┐
│ 搜索城市                     │
├────────────────────────────┤
│ 全国                         │
│ 华东                         │
│ 上海   合肥   杭州   南京     │
│ 华南                         │
│ 广州   深圳   厦门   海口     │
│ 华北                         │
│ 北京   天津   石家庄           │
└────────────────────────────┘
```

## 交互规则

- 默认选中合肥；收起状态只显示城市名，不显示城市代码、地区、覆盖状态或数据层级。
- 面板顶部提供“搜索城市”，输入“合”“深”等即可过滤。
- 城市按地区分组，但分组只作为视觉导航，不写入选中值。
- 面板固定最大高度，超过后在面板内部滚动，不撑长页面。
- 桌面端使用输入框下方的浮层；移动端使用底部抽屉或全宽浮层。
- 选择城市后立即关闭面板，只刷新城市基准卡，不重置工资、扣缴和支出输入。
- 全国作为单独的首选项，不显示“回退”或“覆盖”字样。

## 无障碍要求

自定义选择器必须具备：

- `role="combobox"`
- `aria-expanded`
- `aria-controls`
- 可见的 `label` 与 `htmlFor`
- `Escape` 关闭面板
- `Enter` 打开或确认选择
- 上下键移动选项，焦点状态清晰
- 点击外部区域关闭，但不能阻止键盘操作

如果实现成本过高，宁可保留原生 `<select>` 并限制宽度，也不要做一个键盘不可用的伪下拉框。

## 完成定义

- 输入区域不再出现一条很长的原生城市下拉列表。
- 选择器打开时页面主体不被撑长。
- 30 个城市仍然全部可选，不通过分页隐藏城市。
- 选项只显示“全国”和城市名。
- 桌面端和移动端均可用键盘/触控完成选择。
- 不改城市数据解析器，只改前端交互层。
