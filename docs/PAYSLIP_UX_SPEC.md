## 一、估算引擎（加进 `src/domain/salarySlip.ts`，纯确定性函数）

### 1.1 个税：全国统一月度预扣近似公式（这是真公式，不是拍脑袋）

```
应纳税所得额 taxable = max(0, 税前 − 5000 − 社保公积金个人合计 − 专项附加扣除)
```

月度税率表（速算扣除法）：

| taxable 区间 | 税率 | 速算扣除 |
| --- | --- | --- |
| ≤ 3,000 | 3% | 0 |
| 3,000 – 12,000 | 10% | 210 |
| 12,000 – 25,000 | 20% | 1,410 |
| 25,000 – 35,000 | 25% | 2,660 |
| 35,000 – 55,000 | 30% | 4,410 |
| 55,000 – 80,000 | 35% | 7,160 |
| > 80,000 | 45% | 15,160 |

结果四舍五入到元。函数签名：`estimateMonthlyTax(gross, socialAndFundTotal, extraDeduction = 0): number`。
**标注口径（必须展示）**："按月度预扣近似；实际为累计预扣，年中各月会有差异，以工资条为准。"

### 1.2 社保公积金：通用比例估算（可调、可覆盖）

```ts
type EstimateRatios = { pension: 0.08, medicalIns: 0.02, unemploymentIns: 0.005, housingFund: 0.12 }
estimateDeductions(gross, ratios = 默认值, extraDeduction = 0): PayslipPeriodInput
```

- 缴费基数默认 = 税前（假设写明：各城市有基数上下限，超限时以工资条为准）
- 公积金比例做成 5%–12% 整数档下拉，默认 12%
- 医疗大病附加等城市零头差异不建模，统一归入"以工资条为准"

### 1.3 下一阶段"按当前实际比例推算"（杀手锏，零假设）

```ts
deriveEffectiveRates(current: PayslipPeriodInput): EstimateRatios | null  // current.gross <= 0 时返回 null
```

- 从用户**当前期真实扣缴**反推个人实际费率（养老/医疗/失业/公积金 ÷ 税前）
- 套到下一期税前得到四险一金估算；**个税不按比例缩放**（累进的），用 1.1 公式重算
- 其他扣缴默认沿用当前期金额
- 这条路径用的全是用户自己的数据，无任何城市假设——优先推荐给用户

### 1.4 诚实规则

- 估算只是**预填输入框**，`computePayslip` 的口径不变：以输入框里的金额为唯一事实源
- 每个被估算填充的框带"估"角标；用户手改过的框视为用户输入，角标消失
- 估算是显式按钮触发，不做输入时的静默自动重算（税前改了就在按钮旁提示"税前已变，可重新估算"）

## 二、面板交互（`PayslipPanel.tsx`）

1. 表格上方引导行（替换现"照工资条抄数即可…"）：
   > 手边有工资条：直接抄数最准。没有的话 →【按通用比例估算】（通用口径可修改）
2. "现在"列头按钮：**按通用比例估算**（弹出/内联公积金比例档位 + 可选专项附加扣除输入，默认 0）
3. "下一阶段"列头按钮：**按当前比例推算**（current.gross ≤ 0 时禁用并提示先填当前期）
4. "填入示例"改为：填入税前 10000 → 11000 后**调用估算引擎**生成（示例与公式自洽；不再手写魔法数字）
5. 估算值角标"估"，悬停提示口径；负到手告警保留

## 三、版面收拾（`App.tsx` + `styles.css`）

1. **收入切换缩小**：删掉收入区整排大 tab，改为 legend 行右侧小号分段开关（`到手 ｜ 工资条`，高度 ~24px，同 field-unit 字号）——与顶部模式 tab 拉开视觉层级

3. 移动端：两个估算按钮可换行；工资条网格保持三列不横滚

## 四、测试（`runTests.ts` 追加组 9）

1. 个税公式边界：taxable ≤ 0 → 0；3000 档界（3000→90 元）；跨档连续性（12000/25000 界）；含专项附加扣除
2. 通用比例估算自洽：gross 10000，默认比例 → 养老 800/医疗 200/失业 50/公积金 1200/个税 83（taxable 2750 × 3% = 82.5 → 83）→ 到手 7667
3. 推算路径：当前期任意真实金额 → deriveEffectiveRates → 下一期估算 → computePayslip 恒等式仍成立
4. 用户覆盖优先：估算后手改任一框 → 汇总按手改值计算
5. current.gross = 0 时 deriveEffectiveRates 返回 null、按钮禁用逻辑
