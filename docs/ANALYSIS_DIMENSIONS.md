# Real Raise 分析维度契约

更新时间：2026-07-25

这份文档是产品和数据的连接层。它规定“涨薪还剩多少？”到底分析什么，不把项目扩成没有用户问题的数据大屏。

## 核心问题

用户只需要回答：

> 工资上涨后，扣掉我的真实房租和生活成本，我到底有没有变得更宽裕？

## 第一层：个人确定性计算

这些指标必须由 `src/domain/livingCost.ts` 确定性计算，不能交给模型重算：

| 指标 | 含义 |
| --- | --- |
| 名义收入涨幅 | 下一阶段收入相对当前收入的变化 |
| 当前月结余 | 当前收入减当前房租和其他月支出 |
| 下一阶段月结余 | 下一阶段收入减预计房租和膨胀后的其他支出 |
| 月度结余变化 | 下一阶段月结余减当前月结余 |
| 年度结余变化 | 月度结余变化乘 12 |
| 总支出涨幅 | 房租和其他支出的合计变化 |
| 真实购买力变化 | 收入涨幅相对于个人总支出涨幅的变化 |
| 涨薪被房租吃掉 | 房租增量除以工资增量；工资不增加时不显示百分比 |
| 保本收入 | 在保持当前结余的前提下，下一阶段至少需要的收入 |

## 第二层：官方基准解释

国家统计局数据只用于解释和对比，不覆盖用户输入的真实房租：

1. **收入轨迹**：2021–2025 年全国、城镇、农村人均可支配收入、中位数和人均消费支出。
2. **消费结构**：全国八类人均消费支出金额、占比和同比变化；有官方表 2 的年份再展示城乡八类金额。
3. **价格压力**：全国八类 CPI 年度同比涨跌幅，按年度和类别排序。
4. **非房租基准**：用用户输入的“其他支出”作为金额基数，用已核验的非居住类别价格变化做加权估算，并明确标注“基于官方类别权重的估算”。
5. **房租边界**：用户的当前房租和预计房租优先；官方“居住”或“租赁房房租”只作为宏观参考，不能说成用户房租预测。

## 第三层：产品展示顺序

结果页按决策顺序展示，不按数据表顺序展示：

1. **一句话结论**：名义涨薪是多少，真实购买力是上升还是下降。
2. **钱去了哪里**：工资增加、房租变化、其他生活成本变化对月结余的贡献。
3. **保本线**：下一阶段至少需要多少收入才能维持当前生活水平。
4. **可调整杠杆**：工资、房租、通勤/其他支出变化对年度结余的影响。
5. **官方背景**：相关年份、统计范围和来源链接；模型只能解释，不能修改数字。

## 当前版本不做

- 不做城市房租预测，不伪造北京、上海等城市数据。
- 不做个人银行流水上传，不做信用、投资或借贷建议。
- 不做实时抓取和复杂数据库，不为了“数据平台”而增加数据源。
- 不让 InfiniSynapse 负责加减乘除；它只负责基于已计算结果生成解释和对比。
- 不因为历史数据扩充就改变 `livingCost.ts` 的核心公式。

## 验收标准

- 每个官方数字都有年份、范围、单位和来源 URL。
- 官方值、派生值、用户输入值在数据结构和页面文案中可区分。
- 全国八类消费金额合计与官方总消费支出一致，允许四舍五入误差。
- 任何一个输入变化都能追溯到结果页对应指标的变化。
- 先完成本地确定性计算，再接 InfiniSynapse 的解释层。
