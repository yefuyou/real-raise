# Real Raise 分析维度契约

更新时间：2026-07-26

## 核心问题

> 税前涨薪经过个税、社保、公积金和生活支出之后，真正多了多少可支配的钱？

这不是一个房租计算器，也不是宏观 CPI 大屏。住房支出只是用户可以打开或关闭的固定支出项。

## 第一层：本地确定性计算

当前 MVP 使用到手收入模式：

| 指标 | 定义 |
| --- | --- |
| 到手收入变化 | 下一阶段到手收入 − 当前到手收入 |
| 日常支出变化 | 用户日常支出 × 2026H1/用户自定义变化率 |
| 住房/固定支出变化 | 用户输入的可选固定支出变化 |
| 当前可支配结余 | 当前到手收入 − 当前固定支出 − 当前日常支出 |
| 下一阶段可支配结余 | 下一阶段到手收入 − 下一阶段固定支出 − 下一阶段日常支出 |
| 真实购买力变化 | 到手收入变化与个人总支出变化的相对结果 |
| 保本收入 | 下一阶段固定支出与日常支出 + 当前结余 |

下一阶段工资条模式新增：

| 层级 | 说明 |
| --- | --- |
| 税前工资 | 用户当前与下一阶段的税前月工资 |
| 法定扣缴 | 个税、养老、医疗、失业、公积金等，允许按工资条直接输入 |
| 到手现金 | 税前工资 − 当月扣缴 |
| 延迟/保障价值 | 养老、公积金等不应简单标记为“消失”，单独展示为保障或资产积累 |

## 第二层：官方数据与城市基准

### 全国/城镇观察基准

- 2021–2025 年收入、消费结构与 CPI 历史数据。
- 2026 年上半年八类 CPI 已公布同比数据。
- 2026H1 基准只作为日常支出估算起点，不代表全年或下一年度预测。

### 城市数据三档口径

1. **城市分类基准**：城市与月份、类别均有官方来源时使用。
2. **城市综合基准**：只有城市综合 CPI 时，只展示综合价格背景，不拆八类。
3. **全国/城镇回退**：城市数据缺失时使用全国或城镇基准，并在 UI 标出“回退”。

国家统计局国家数据明确提供“主要城市月度价格”和“主要城市年度数据”入口，但并不意味着每个城市、每个类别、每个月都有同样完整的公开值。实现时必须以实际下载并核验的数据为准。

### 住房边界

- 用户输入的住房/固定支出优先。
- 城市 CPI 的“居住”类别只作宏观解释。
- 城市房价指数不用于推导个人租金或住房支出。

## 第三层：InfiniSynapse 解释任务

InfiniSynapse 可以：

- 读取已启用的全国/城市公开数据。
- 解释用户的扣缴和日常支出压力来源。
- 对比用户与全国、城镇或城市基准。
- 生成带年份、范围和来源的情景说明。

InfiniSynapse 不可以：

- 重新计算本地金额。
- 把预测写成官方数据。
- 用城市平均值覆盖用户实际输入。
- 把养老、公积金简单算成损失。

## 当前不做

- 不做所有城市的实时抓取。
- 不做城市房租预测和房价预测。
- 不硬编码全国统一社保、公积金比例。
- 不上传个人工资条、银行流水或真实缴费记录到公共数据源。
- 不因为想“像数据平台”而接入没有明确决策价值的数据。

## 验收标准

- 任何官方数字都有年份、范围、单位、来源 URL。
- `verified`、`derived`、`user-input`、`forecast` 在数据结构和文案上可区分。
- 城市数据缺失不导致页面报错，回退层级可见。
- 任何用户输入都能追溯到结果页的对应指标。
- 核心数字由本地公式产生，平台只提供解释。
