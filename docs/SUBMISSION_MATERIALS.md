## 一、报名表信息

**应用名称**：Real Raise · 真实涨薪——到手收入诊断器

**一句话介绍**：你的涨薪，消失在到手之前了吗？把税前工资、扣缴和生活支出拆开，看清真正落袋的钱。

**应用描述（报名表用，约 300 字）**：

> 工资条上的涨幅，不等于银行卡里多出来的钱。Real Raise 面向中国职场人，把一次涨薪拆成一条可核对的链路：**税前工资 → 个税/社保/公积金 → 真正到手 → 日常生活支出 → 可支配结余**，30 秒回答"这次涨薪，真正留在我手里的还有多少"。
>
> 与常见 AI 数据应用不同，Real Raise 坚持"**数字由确定性公式负责，AI 只解释、不改数**"：所有金额由本地可验证公式计算；InfiniSynapse 作为解释层由 Cloudflare Worker 在服务端调用 Server API，产出带来源的解释与三份可下载产物（explanation.md / evidence.csv / analysis-manifest.json）。项目 API Key 始终保存在服务端 Secret；评委使用随报名材料提供的口令换取短时签名会话后即可实时运行。额度受限时，应用会明确降级到带任务 ID 的真实存档回放，绝不冒充实时结果。
>
> 数据侧执行严格的四分法：官方核验原值（verified）、派生估算（derived）、用户输入（user-input）、情景预测（forecast）逐字段标注，来源可点击；已接入 2021–2025 官方历史基准、2026H1 全国八类 CPI，以及北京/上海/深圳/合肥城市样本——城市数据缺失时诚实回退全国基准并明确提示，绝不插值冒充。
>
> 官方统计基准双轨登记：演示账号以**平台数据源 + 知识库**承载（含数据口径说明，任务可核验），服务端实时任务以固定 Prompt 与来源索引保证口径稳定；SSE 实时任务进度；每日硬上限、并发保险丝和真实回放保护额度；自动化断言 + TypeScript 严格检查保证公式稳定。

**（可选）如果表单有"应用亮点/技术亮点"栏，按评分四维填**：

- 创新性：反向切口——不做记账、不做大屏，回答一个所有人都在问的问题；"确定性计算 + AI 解释"分离架构，从设计上杜绝 AI 编数字。

## 三、评委答辩速答卡（预判 8 问）

1. **和记账 App / BillLens 们有什么区别？**——他们看"过去花了多少"，我们回答"这次涨薪之后会怎样"：是面向一次决策的前瞻诊断，不是流水记录；且所有数字可溯源。
2. **AI 会编数字吗？**——不会进入结果。金额全部来自本地确定性公式，AI 的输出只用于解释，prompt 硬约束"不得重算或修改本地数字"，解释与数字分离渲染。
3. **InfiniSynapse 具体用在哪？**——浏览器只调用 Real Raise Worker；Worker 使用服务端 API Key 建立 InfiniSynapse SSE、下发任务、读取 Task Workspace 三产物；官方统计 CSV 与数据口径文档以**数据源 + 知识库**形式登记在演示账号；平台任务后台可查每次调用（回放附任务 ID）。它是解释层与数据源接入层，不是计算器。
4. **为什么不让 AI 算？**——个税、社保、结余是强确定性问题，用大模型算是把可验证的事变成不可验证的事；我们把 AI 用在它擅长的：跨数据源解释与对比。
5. **城市数据不全怎么办？**——三档口径：有核验城市分类用城市值；只有综合 CPI 只作背景；都没有回退全国基准并明确提示。绝不插值冒充，也不拿省数据替代城市。
6. **数据可信度？**——每个字段带年份、统计范围、来源 URL，verified/derived/user-input/forecast 四分法标注；2025 农村中位数官方未单独公布，我们就显示"未单独公布"而不是编一个数。
7. **商业化路径？**——个人免费诊断获客；付费点：城市规则包（社保公积金基数规则）、报告导出、跳槽比 Offer 高级场景；B 端可给招聘/薪酬平台做嵌入组件。
8. **额度怎么保护？**——只有持有效评委短时会话的请求能进入真实链路；再叠加每分钟限速、北京时间每日硬上限和全局并发保险丝；超限后明确切到真实回放/本地演示，不继续消耗额度。
9. **API Key 会暴露吗？**——不会。Key 只作为 Cloudflare Worker Secret 存在；浏览器网络面板只能看到 Real Raise 自己的 `/api/analysis`，看不到 InfiniSynapse Authorization。评委口令也不进入构建产物，只在服务端验证。
