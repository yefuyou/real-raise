# 首页首屏与 AI 解读布局方案

## 已确认的问题

当前 `App.tsx` 的结果区顺序是：

```text
结果标题
→ 诊断链
→ 四张指标卡
→ 瀑布图
→ 城市价格基准 Tab
→ AI 生活解读
```

而 `styles.css` 中顶部还有约 84px 的 `topbar`，Hero 设有约 280px 的最小高度。移动端输入区和结果区会改为上下堆叠，因此这些高度会全部累加。用户必须滚动很久，才能看到项目的主要功能“AI 生活解读”。

## 设计决策

### 1. 删除独立的功能型顶栏

当前顶栏没有导航作用，只有重复项目标题、AI 开关和本地运行状态。它不应该单独占一整行。

- 桌面端保留极简品牌标识 `REAL RAISE`，高度压缩到一行；不再重复完整主标题。
- 移除顶栏中的 `AI 解读预览` 开关和运行状态；这些属于 AI 解读卡内部的操作状态。
- 移动端不保留独立顶栏，品牌标识并入 Hero 的眉题或标题上方。

### 2. Hero 改成紧凑导语

Hero 只负责让用户知道“这是算什么的”，不负责占据首屏空间：

- 移除或隐藏装饰性 stamp；
- 去掉固定的 `min-height: 280px`；
- 移动端标题、说明和第一个输入区之间保持紧凑间距。

### 3. AI 生活解读前移

结果区的推荐顺序改为：

```text
结果标题与真实购买力结论
→ AI 生活解读（主要功能）
→ 关键指标
→ 诊断链/瀑布图
→ 当前城市 / 历史参考 Tab
```

`InsightSection` 默认应该紧跟主结论出现。未开启远程任务时仍显示本地 Mock 解读入口；开启后，生成、进度、完成、失败和来源状态都在这张卡内完成。

### 4. 细节降级，而不是继续堆在主路径上

诊断链、瀑布图和价格基准仍然保留，但它们是解释层，不是首屏第一行动。手机端可以使用折叠区或在 AI 解读之后展示，不能把主要功能推到最后。

## 完成定义

- 用户在手机上打开页面后，第一屏能看到主标题、简短说明和输入入口。
- 点击计算后，页面自动定位到结果区，并在结果标题下面直接看到“AI 生活解读”。
- 顶栏不再重复完整主标题，也不承载 AI 开关。
- Hero 不再使用大块固定最小高度把输入区往下推。
- AI 解读卡的 loading、error、completed 状态仍然保留并可访问。
- 不改变计算公式、数据源、InfiniSynapse API 契约或金额数字。
