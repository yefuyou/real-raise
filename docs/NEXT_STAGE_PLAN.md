# 下一阶段工作计划：到手收入诊断器

更新时间：2026-07-26

## 0. 本阶段决策

产品主标题冻结为：

> **你的涨薪，消失在到手之前了吗？**

产品主线从单一住房支出叙事改为：

```text
税前工资
  → 个税 / 社保 / 公积金
  → 到手收入
  → 日常生活支出
  → 可支配结余
```

住房支出保留为可选因素，和交通、食品、医疗、教育等一起属于生活支出中的一个维度，不再成为首页主结论。

## 1. 真实状态，不假装已经完成

当前版本已经有稳定的“到手收入 + 固定支出 + 日常支出”确定性计算，但还没有真正接入城市扣缴规则。下一阶段分两步：

### A. 工资条模式

先让用户直接输入工资条上已经扣掉的项目：

- 税前工资
- 个人所得税
- 养老保险
- 医疗保险
- 失业保险
- 住房公积金
- 其他扣缴

这样不需要我们先猜每个城市的缴费基数，也能真实回答“涨薪后到手变了多少”。

### B. 城市规则模式

在有官方来源、有效期和适用范围后，再为城市提供估算：

- 工资基数上下限
- 个人/单位缴费比例
- 个税专项附加扣除
- 公积金缴存比例和基数

城市规则模式必须显示“估算”，并允许用户用工资条实际扣缴额覆盖它。

## 2. 城市数据是否可用

可以用，但不能简单理解为“每个城市都有完整八类月度 CPI”。国家统计局国家数据提供：

- 主要城市月度价格
- 主要城市年度数据
- 分省月度、季度和年度数据

国家统计局也明确答复，主要城市 CPI 可在“国家数据 → 地区数据 → 主要城市月度价格”中自行设定指标和时间、注册后下载。具体入口：[国家数据主要城市月度价格](https://data.stats.gov.cn/easyquery.htm?cn=E0104)。

同时，各地统计局或国家调查队会发布本地 CPI 月报，例如北京调查总队发布 2026 年 6 月北京 CPI 月报。因此我们采用以下实现顺序：

1. 首批扩展到 30 个资料可核验的城市，**先完成合肥（340100）闭环**，再做覆盖面并按数据完整度分层。
2. 先接城市综合 CPI；只有八类齐全时才做分类权重计算。
3. 每条数据保留 `cityCode`、`period`、`category`、`value`、`scope`、`sourceUrl`。
4. 城市缺项时回退到全国/城镇基准，不插值冒充官方值。
5. 城市数据只解释日常价格背景；用户住房支出仍由用户填写。

当前已落地的全国扩展样本：北京（`110000`）和深圳（`440300`）2026H1 综合/八类齐全；上海（`310000`）2026H1 有综合 CPI `+0.8%`、202606 有八类月度样本，因此上海 H1 分类请求仍按类别回退全国基准；合肥继续保留 2024 历史样本与全国回退链路。

推荐首批城市：**合肥（第一优先）**、北京、上海、广州、深圳、天津、重庆、成都、杭州、南京、武汉、西安、苏州、宁波、青岛、济南、郑州、长沙、福州、厦门、昆明、贵阳、南宁、海口、石家庄、太原、沈阳、大连、长春、哈尔滨。它们不是“全国代表性排名”，只是覆盖主要区域、便于核验的第一批样本。

城市数据按三档交付：

- A 档：八类 CPI 和综合 CPI 都有已核验值，可参与分类估算。
- B 档：有城市综合 CPI 和部分分类值，只展示实际覆盖部分。
- C 档：只有城市年度/收入背景，日常支出计算回退到全国或城镇基准。

因此“补 30 个城市”不等于要求 30 个城市都必须有完整八类数据；页面会诚实显示每个城市的覆盖等级。执行上先做合肥专项包，再分三批推进其余城市：先补城市元数据和综合 CPI，再补分类 CPI，最后补收入/消费基准。

## 3. 2026 CPI 的使用方式

截至 2026-07-26，国家统计局已公布到 6 月。2026 年 1—6 月全国 CPI 同比上涨 1.0%，八类基准已在 `src/data/official2026.ts` 登记。

已公布的 1—6 月同比值：

| 类别 | 同比 |
| --- | ---: |
| 食品烟酒及在外餐饮 | -0.2% |
| 衣着 | +1.6% |
| 居住（宏观基准） | -0.2% |
| 生活用品及服务 | +1.9% |
| 交通通信 | +1.8% |
| 教育文化娱乐 | +1.2% |
| 医疗保健 | +2.0% |
| 其他用品及服务 | +11.6% |

这些是已公布观察值。产品默认值用 2025 年城镇消费结构进行加权，但不把这个派生值称为“个人真实通胀”。下半年和下一阶段由用户调整，后续可增加低/中/高三档情景，而不是写一个看似精确的预测数字。

来源：[国家统计局 2026 年 6 月 CPI](https://www.stats.gov.cn/sj/zxfbhjd/202607/t20260709_1964084.html)。

## 4. 页面调整

### 4.0 用户真正看到的城市流程

城市不是一个独立的数据研究模块，而是工资与生活支出计算的输入条件：

```text
填写工资/扣缴
      ↓
选择所在城市（默认合肥）
      ↓
旁边显示该城市当前 CPI 价格基准卡
      ↓
计算到手收入、日常支出与可支配结余
```

用户界面不展示“首批 30 城覆盖矩阵”、数据覆盖地图或 `A-history / B-current / C-fallback` 等内部术语。城市缺项只用人话提示“该城市当前分类数据暂缺，已使用全国基准”，并保留来源链接。30 城目录和覆盖层级继续留在数据契约中，供后端、来源抽屉和内部验收使用。

### 首页输入

- 标题：你的涨薪，消失在到手之前了吗？
- 收入标签：到手收入 / 月（当前 MVP）
- 下一阶段：下一阶段预计，不再强行写“明年”
- 住房标签：住房支出（可选）
- 其他标签：日常生活支出（不含住房）
- 提示：默认基准来自 2026H1 已公布 CPI，可手动调整，不是官方预测。

### 结果页

最先展示：

1. 到手收入增加多少。
2. 每月/每年可支配结余变化。
3. 维持当前生活水平需要多少到手收入。
4. 收入变化、固定支出、日常支出分别贡献了多少。

后续工资条模式再增加：

```text
税前工资变化
− 个税变化
− 社保公积金变化
= 到手收入变化
```

养老和公积金另列“未来保障/账户积累”，不把它们全部称为消失。

### 城市基准卡

城市卡应显示：

- 城市与数据期间。
- 城市综合 CPI 或城市八类 CPI 的实际覆盖范围。
- 用户支出结构与城市/全国基准的差异。
- “城市数据不可用时已回退到全国基准”的明确提示。
