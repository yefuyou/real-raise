# 哈吉米前端测试审查清单

这不是要求重复跑整套测试的脚本，而是 Codex 验收哈吉米提交时检查的最小覆盖矩阵。每次只看新增行为是否有对应断言或可复现证据。

## P0 必须覆盖

| 场景 | 关键断言 |
| --- | --- |
| 合肥历史期 | 2024 `A-history` 显示真实期间和来源，不显示为 2026H1 |
| 合肥当前期缺项 | 2026H1 每个缺失类别显示 `C-fallback` / 全国基准回退，不出现安徽省替代 |
| 全国目录 | 未核验城市可选择，但不能生成伪造城市数值；城市卡显示待核验或全国回退 |
| 本地计算权威 | AI/解释文本不能改变 `LivingCostResult` 的收入、扣缴、支出和结余数字 |
| 失败与重试 | failed 状态可见，retry 后不会重复叠加金额或留下旧错误 |
| 空/加载/手机 | 无数据、加载、失败、窄屏均有可读状态，不依赖 hover 才能操作 |

## P1 应覆盖

- 来源链接可点击，年份、范围和数据期间相互一致。
- 城市卡同时展示“城市原值”和“全国回退”时，不使用同一视觉标签混淆。
- 详细模式六类 CPI 修改只影响对应分类和派生支出，不改收入、扣缴、住房用户输入。
- 取消任务后不会在延迟事件到达时把状态重新写回 completed。
- EventSource 失败后重试只建立一个订阅，不重复渲染进度和产物。
- 键盘可聚焦、对话框 Esc、焦点恢复和外链安全属性没有回归。

## Codex 的最小验收顺序

1. 先静态读测试用例和 diff，确认断言真的走过状态转移，而不是只检查函数存在。
2. 检查 `git diff --check` 和最小 `npm run verify` 证据。
3. 仅在 P0 证据缺失时让哈吉米补测试；不为已经有证据的路径反复重跑全量构建。
