# 文档治理规则

> 状态：已接受
> 决策日期：2026-07-30
> 适用范围：Real Raise 的产品、数据、平台接入、发布和交接文档

## 开始任务前的固定阅读顺序

1. [文档中心](./README.md)
2. [产品规格](./product/PRODUCT_SPEC.md)
3. [状态机](./product/STATE_MACHINES.md)
4. 与任务相关的 [ADR](./decisions/README.md)
5. [最新 Checkpoint](./checkpoints/2026-07-30-baseline.md)
6. 相关技术契约或数据资产说明

若任意两篇互相矛盾，先登记漂移，不得挑一篇顺手的旧方案直接实现。

## 每篇现行文档必须包含

- `状态`：草案 / 已接受 / 已废弃 / 历史快照。
- `最后核验`或`决策日期`。
- `适用范围`。
- 目标状态与当前实现不一致时，必须列出差异。
- 关联实现、测试或来源。

## 更新触发器

| 发生的变化 | 必须同步 |
| --- | --- |
| 产品路径、按钮或状态改变 | 产品规格、状态机、Changelog |
| 认证或密钥边界改变 | ADR、状态机、部署手册、Checkpoint |
| Prompt、上下文或公式版本改变 | 技术契约、Checkpoint、回放清单 |
| 新录制或迁移回放 | Replay 规则、Changelog、Checkpoint |
| 城市或官方数据改变 | 数据资产目录、数据契约、来源文件 |
| 合并或部署 | Changelog、Checkpoint |
| 发生回滚或重大线上故障 | Changelog、Checkpoint、Retrospective |

## 文档类型的写入规则

### 产品规格

- 使用稳定需求 ID，例如 `RR-AUTH-001`。
- 需求描述“用户必须能做什么”，不写组件实现。
- 每项核心需求必须有可观察验收结果。

### 状态机

- 状态名不得混入动作，例如使用 `completed-stale`，而不是“点击重新生成”。
- 每个事件必须声明前置状态、目标状态和 UI 行为。
- 运行模式、认证状态和报告状态分开建模，不能压成一个布尔值。

### ADR

- 一条 ADR 只记录一个重大决定。
- 已接受 ADR 不覆盖重写；改变决定时新增 ADR 并标记取代关系。
- “代码尚未实现”不等于“决定不存在”，但必须明确 implementation gap。

### Changelog

- 只记录已经发生的修改、合并、发布或回滚。
- 不把计划写成已完成。
- 每项尽量附 commit、PR 或 Checkpoint。

### Checkpoint

Checkpoint 至少记录：

- 时间与观察者；
- 分支、commit、PR 状态；
- 工作树是否干净；
- 生产 URL 与健康状态；
- 公式、Prompt、上下文、回放版本；
- 测试证据；
- 未决问题和禁止假设。

## 禁止事项

- 禁止整篇重写别人的文档而不先读取磁盘最新版本。
- 禁止用“当前”“已经完成”“已部署”而不给 commit、时间或运行时证据。
- 禁止把历史方案的完成清单继续当现行需求。
- 禁止把 `replay.v2` 包装版本写成“当前 Prompt 录制版本”。
- 禁止把前端隐藏写成“后端能力已删除”。
- 禁止在文档中写入 API Key、Cookie、Secret、完整用户工资或未脱敏日志。
