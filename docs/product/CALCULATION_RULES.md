# Real Raise 计算规则

> 状态：Active
> 最后核验：2026-07-30
> 真相源范围：产品当前确定性金额、比例、估算与取整口径
> 代码依据：`src/domain/livingCost.ts`、`src/domain/salarySlip.ts`

## 1. 权威边界

- 用户输入、工资条和城市数据是输入事实。
- Real Raise 代码负责全部金额、比例和情景矩阵。
- InfiniSynapse 只能排序、比较、解释，不得覆盖计算结果。
- 页面、Worker、回放凭证必须记录计算版本；版本不一致时不得静默混用。

## 2. 到手收入模式

设：

- `currentIncome`：当前月到手收入；
- `nextIncome`：下一阶段月到手收入；
- `currentRent` / `nextRent`：当前与下一阶段月住房支出；
- `otherSpend`：当前月其他支出；
- `otherInflationRate`：其他支出变化率。

```text
当前总支出 = 当前房租 + 当前其他支出
下一阶段其他支出 = 当前其他支出 × (1 + 其他支出变化率)
下一阶段总支出 = 下一阶段房租 + 下一阶段其他支出
当前结余 = 当前到手收入 - 当前总支出
下一阶段结余 = 下一阶段到手收入 - 下一阶段总支出
月结余变化 = 下一阶段结余 - 当前结余
年结余变化 = 月结余变化 × 12
```

若存在用户明确输入的下一阶段其他支出覆盖值，且其为有限非负数，则覆盖 CPI 推算。

## 3. 解释指标

```text
收入增长率 = 下一阶段收入 / 当前收入 - 1
总支出增长率 = 下一阶段总支出 / 当前总支出 - 1
真实购买力变化率 = 月结余变化 / 当前到手收入
房租分走涨薪比例 = 房租增加额 / 到手收入增加额
保本收入 = 下一阶段总支出 + 当前结余
```

分母小于等于零时，相应增长率回退为 `0`；到手收入没有增加时，“房租分走涨薪比例”为 `null`，页面不得伪造百分比。

“真实购买力变化率”只是把结余变化按当前收入归一化。绝对金额仍是主结论。

## 4. 工资条模式

工资条实际值优先：

```text
扣缴合计 = 个税 + 养老 + 医疗 + 失业 + 公积金 + 其他扣缴
到手收入 = 税前工资 - 扣缴合计
税前增加额 = 下一阶段税前 - 当前税前
到手增加额 = 下一阶段到手 - 当前到手
涨薪保留率 = 到手增加额 / 税前增加额
```

税前没有增加时，涨薪保留率为 `null`。任一期扣缴超过税前工资时，必须显示负到手校验提示。

养老和公积金变化属于未来账户积累的一部分，不得笼统写成“被吃掉”或“消失”。

## 5. 工资条估算

估算只用于预填，用户可用真实工资条覆盖。默认个人比例：

| 项目 | 默认比例 |
| --- | ---: |
| 养老 | 8% |
| 医疗 | 2% |
| 失业 | 0.5% |
| 公积金 | 12% |

公积金可选 5%–12%。月度个税采用月度预扣近似：

```text
应纳税所得额 = max(0, 税前 - 5000 - 四险一金 - 专项附加扣除)
月个税 = 应纳税所得额 × 税率 - 速算扣除数
```

实际个税为累计预扣，年中月份可能不同；页面必须标注“估算，以工资条为准”。

## 6. 城市与 CPI

- 城市只用于选择适用的公开统计基准，不替代用户真实支出。
- 匹配不到城市时按城市契约回退到全国基准。
- 期间、覆盖层级和 `source_id` 必须随结果展示。
- 城市目录和来源以 [城市基准契约](../data/CITY_BENCHMARK_CONTRACT.md) 为准。

## 7. 格式与边界

- 金额展示按元四舍五入，内部计算保留 JavaScript 数值精度。
- 百分比默认保留 1 位小数；审计产物可保留更高精度。
- 非有限输入在领域计算中按 `0` 清洗，但界面必须优先阻止非法输入。
- 支出或收入为负、金额极端、扣缴超过税前时必须给出明确校验，不得交给模型自行解释。

## 8. 修改规则

任何公式修改必须同时完成：

1. 更新领域代码与测试；
2. 更新本文件和计算版本；
3. 更新 Worker 的同源计算；
4. 审计全部 replay；
5. 在 Changelog 和 ADR 中记录兼容策略。
