# Real Raise 界面设计规则

> 状态：Active
> 最后核验：2026-07-30
> 真相源范围：当前页面的信息层级、交互边界和关键状态

## 1. 页面目标

首屏帮助用户完成输入，结果区帮助用户用一句话理解“真正多留下多少钱”，AI 区帮助用户在明确来源和边界的前提下获得进一步诊断。

## 2. 信息优先级

1. 月度真实新增结余；
2. 年度真实新增结余；
3. 收入、扣缴、房租和其他支出的驱动拆解；
4. 城市/全国基准与数据期间；
5. AI 报告正文、情景和凭证。

比例用于解释，不得压过绝对金额。

## 3. 主操作

| 状态 | 主操作 | 次操作 |
| --- | --- | --- |
| 未输入 | 使用预设案例或填写数据 | 切换收入模式 |
| 已计算、未登录 | 登录生成个人报告 | 查看精确回放 |
| 已登录、无报告 | 选择模型并生成报告 | 查看回放 |
| 任务运行中 | 查看进度 | 安全停止 |
| 报告完成 | 阅读和下载凭证 | 按当前数据重新生成 |
| 输入已变更 | 生成新报告 | 查看上一份报告 |
| 任务失败 | 重试 | 返回上一份成功报告 |

## 4. 预设案例

预设不是随机演示数字，每个案例必须验证一个明确命题：

- 税前涨幅较高，但扣缴显著稀释到手增量；
- 固定支出上涨，吞掉大部分到手涨薪；
- 房租稳定、日常支出上涨，结余改善有限；
- 收入增加足以跨过保本线。

每个预设需记录：用户画像、命题、输入、预期核心结论和适配的回放任务。未完成这五项的案例不得进入页面。

## 5. 城市选择

- 用户只选择自己所在城市；
- 当前城市、数据期间和全国回退必须可见；
- 城市选择器的默认值、搜索和键盘操作必须一致；
- 不允许把宏观平均描述成个人合理支出标准。

历史设计见 [城市选择器实施稿](../archive/CITY_PICKER_UX_2026-07-26.md)。

## 6. AI 区

未登录时显示登录和回放，不显示认证探测错误。已登录时同时保留：

- 用户身份；
- 模型选择；
- 个人实时任务；
- 回放入口。

禁止出现 BYOK、填 Key 或默认暴露的 Judge 入口。

报告必须显示执行模式、任务 ID、产物状态、Prompt/上下文版本摘要，以及“平台正文 / Real Raise 数字”的权威边界。

## 7. 报告新鲜度

报告完成后，只要输入签名发生变化：

- 旧报告保留；
- 明确标记为旧输入；
- 主按钮变为“按当前数据生成新报告”；
- 不自动发起任务；
- 新任务失败时不覆盖旧报告。

## 8. 响应式与无障碍

- 手机端保持输入、主结论和主按钮的顺序；
- 折叠区使用原生可访问控件或完整 ARIA 状态；
- 错误提示使用文字，不只依赖颜色；
- 加载状态说明当前阶段和可取消性；
- 触控目标、焦点样式和键盘操作需通过发布检查。
