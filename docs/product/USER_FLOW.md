# Real Raise 用户流程

> 状态：Active
> 最后核验：2026-07-30
> 真相源范围：用户从输入、计算到回放或实时报告的完整路径
> 关联：[产品规格](./PRODUCT_SPEC.md) · [状态机](./STATE_MACHINES.md) · [界面设计](./INTERFACE_DESIGN.md)

## 1. 共同起点：先得到确定性价值

```text
进入页面
→ 选择到手收入模式或工资条模式
→ 选择预设案例，或填写自己的当前/下一阶段数据
→ Real Raise 立即计算收入、扣缴、支出和结余变化
→ 用户先看到“真正多留下多少钱”
→ 再选择回放或登录生成实时报告
```

这一段不依赖模型。用户即使不登录，也必须能理解核心数字、公式边界和数据来源。

## 2. 未登录访客

用户目标：快速判断产品是否有用，且不被登录墙阻断。

页面必须提供：

- 确定性算表；
- Partner SSO 登录入口；
- 与当前输入精确匹配时可用的真实任务回放；
- 回放的任务 ID、录制日期、旧口径提示与来源徽标。

未登录访客不能：

- 发起个人实时任务；
- 看见 BYOK 或填 Key 入口；
- 看见评委专属入口；
- 把本地模板或不完整产物误认成平台完整报告。

## 3. Partner SSO 登录用户

```text
用户主动点击登录
→ 跳转 InfiniSynapse 授权
→ 回到发起登录的原始站点
→ 页面恢复当前输入
→ 用户选择支持的分析模型
→ 发起 Agent 实时任务
→ 展示进度、正文、产物状态与任务归因
```

登录只改变“能否发起个人实时任务”，不能改变确定性计算结果，也不能隐藏回放入口。

## 4. 已有报告后修改输入

任何会改变请求签名的输入都使旧报告进入 `stale`：

```text
报告完成
→ 用户修改工资、扣缴、房租、支出、城市、期间或模型
→ 保留旧报告供对照
→ 明确标记“报告对应旧输入”
→ 显示“按当前数据生成新报告”
→ 用户主动触发下一次任务
```

禁止静默自动消耗额度；也禁止继续把旧报告当作当前结果。

## 5. 用户主动重新分析

重新分析必须是显式动作。开始前页面应说明：

- 将创建一个新任务；
- 使用当前输入和当前模型；
- 旧报告不会被覆盖，直到新任务成功；
- 失败后仍可回到上一个成功结果。

## 6. 失败与恢复

| 失败点 | 页面行为 | 恢复动作 |
| --- | --- | --- |
| 初始认证探测失败 | 不弹全局错误 | 用户主动登录时再提示 |
| 登录失败 | 保留算表和回放 | 重试登录 |
| 实时任务超时 | 标记任务已停止，不称“完成” | 使用当前输入重试 |
| 平台文件缺失 | 标记 `stream-fallback` | 显示事件流正文和缺失项 |
| 回放不匹配 | 不播放近似案例 | 修改为预设输入或登录实时分析 |
| 新报告失败 | 保留上一次成功报告 | 返回旧报告或再次重试 |

## 7. 流程不变量

1. 生产 URL 与登录回跳 origin 必须稳定。
2. 模型选择、SSO、回放是相互独立的能力，修一项不得删除另一项。
3. 页面显示的模式必须与实际执行来源一致。
4. 金额以 Real Raise 确定性计算为准，模型不重算。
5. 用户修改输入后，旧报告不得继续冒充当前报告。
