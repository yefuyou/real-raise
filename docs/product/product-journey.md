## 3. 用户问题如何变化

### 3.1 起点：真实购买力

初始 README 的产品名是“涨薪还剩多少？”，定位为“中国城市租房上班族的个人购买力分析工具”。首版 Hero 问：

> 你的涨薪，被房租吃掉了吗？

它已经有一个正确的核心：不是只看工资增长百分比，而是比较两期最终结余。

但“真实购买力”有三个表达问题：

1. 它容易让人期待宏观购买力指数或复杂经济模型。
2. 页面主公式实际回答的是个人月结余变化，而不是一个通用购买力指数。
3. 工资条、扣缴和固定支出加入后，用户更关心“我到底多留下多少钱”。

### 3.2 收敛：到手链路

PR #3 加入工资条后，产品链路变成：

```text
税前增加
→ 个税/社保/公积金变化
→ 到手增加
→ 住房与日常支出变化
→ 月结余变化
```

这使项目从“输入房租和 CPI 的计算器”转向“真实收入诊断”。

### 3.3 当前应采用的价值表达

**User-provided decision**

- 主问题：为什么工资涨了，我还是越来越穷？
- 用户问题：涨薪以后你真正能多留下什么？
- 中文副标题：涨薪后的生活余量。

推荐的一句话：

> Real Raise 把税前涨薪拆成扣缴、到手和生活支出变化，告诉你下一阶段每月真正能多留下多少钱。

“生活余量”比“真实购买力”更贴近代码中的权威结果 `monthlyRemainderChange`，也降低了宏观经济含义过度承诺。

## 4. 核心与比赛驱动功能

| 类型 | 功能 | 判断 |
| --- | --- | --- |
| 核心 | 两期到手/工资条输入 | 没有它就不能回答产品问题 |
| 核心 | 住房 + 日常支出 | 把名义涨薪转为生活余量 |
| 核心 | 确定性结余、瀑布与保本收入 | 产品结论 |
| 核心支撑 | 数据来源、口径、缺失回退 | 让结果可解释 |
| 可选增强 | Agent 解读、scenario、证据产物 | 帮用户理解，不是算表成立条件 |
| 比赛驱动 | Judge Mode | 方便评委体验项目额度；不是普通用户价值 |
| 比赛驱动 | Partner SSO | 为真实用户数、个人额度和平台归因服务 |
| 已淘汰 | 浏览器 BYOK | 密钥边界不适合公开产品 |
| 默认冻结 | 排行榜、历史记录、分享卡、更多城市、PWA、开放 API | 当前 ROI 低于可信收尾 |

Judge Mode 的工程价值在于逼出服务端 Secret、短时 token、限流与降级设计；产品价值有限。SSO 的工程实现是真实成果，但它把团队注意力从“用户看懂月结余”拉向了比赛用户数。

B 站标题暴露了旧定位：

> 计算真实涨薪对购买力提升的计算器

它同时出现“计算、真实涨薪、购买力、提升、计算器”，用户仍要自行翻译产品用途。更有效的公开视频钩子应直接给冲突和结果：

> 税前涨 1000，为什么每月最后只多留下 266？

### 5.4 与 aimeetup.center 的表达对照

**Observed**：2026-07-30 打开的 [aimeetup.center](https://aimeetup.center/) 首屏直接写“免费在线 SEO 检测，快速定位网页优化问题”，随后给出输入动作和六个检测维度。

**Inferred**

这不证明它是 Real Raise 的直接竞品，但它暴露了表达差距：

- 对象明确：网页；
- 动作明确：粘贴 URL、检测；
- 输出明确：优化问题；
- 时间预期明确：10–30 秒。

Real Raise 的“你的涨薪，消失在到手之前了吗？”有情绪张力，却需要副标题才能说明输入和输出。Portfolio 叙事应保留问题钩子，同时紧接“填两期工资与支出，得到每月生活余量变化”。

## 7. 从比赛项目到 Portfolio

**User-provided decision，2026-07-28**

停止继续追逐登录、注册、排行榜与泛化平台能力，原因不是“项目失败”，而是：

- MVP、线上 Demo、Judge、公开发布已经证明了从 0 到 1 推进；
- 新功能主要优化比赛用户数，不能强化核心价值；
- 工程事实、测试可信度、生产身份和接管能力更适合作品下一阶段目标；
- 继续堆功能会掩盖重复实现、文档漂移与验证缺口。

Portfolio 阶段的完成定义不是 feature count，而是：

1. 陌生维护者能从干净环境启动并理解主链。
2. 核心公式和每个出口有固定输入证据。
3. live / replay / mock / historical 的 provenance 可解释。
4. 生产部署可追到 commit、CI 与 Release。
5. 公开传播和反馈只引用可复核证据。
6. 项目拥有一份能经受面试追问的复盘。

## 8. 60 秒 Demo 与 3 分钟 Case Study

### 60 秒 Demo

只讲产品：

1. 5 秒：税前涨 1000，最后为什么只多留 266？
2. 15 秒：填两期工资条，展示扣缴与到手。
3. 15 秒：加入住房和日常支出，得到月结余变化。
4. 10 秒：展示数字来源和“AI 不改数”。
5. 10 秒：一张 Agent/Replay provenance 与证据下载。
6. 5 秒：结论——涨薪后的生活余量。

### 3 分钟 Case Study

讲决策与接管：

1. 生活问题如何变成 MVP。
2. 为什么确定性公式与 Agent 分层。
3. 如何上线、发布、收到方向信号。
4. 比赛指标为何推动 Judge/SSO。
5. 多 Agent 如何加速，也如何造成重复实现和文档漂移。
6. 审计抓到的真实故障：ALL PASSED 误导、刷新不可恢复、生产 identity 缺失。
7. 为什么主动冻结功能，转为可验证 Portfolio。
